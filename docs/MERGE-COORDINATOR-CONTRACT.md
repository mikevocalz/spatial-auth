# Transactional merge coordinator alpha

`createMergeCoordinator` is a **server-only host integration contract** for two **existing** Better Auth users. It is not an endpoint or a complete migration service. The host must implement `withTransaction` and the same-transaction handlers, with deterministic row locks, unique provider mappings and FK-safe domain transfers.

**Security:** The public caller supplies only merge intent ID and idempotency key. `currentBetterAuthUserId` is the **server's authenticated Better Auth session**, never a client body claim. The stored intent is created after separate source-user proof, recent target reauthentication, explicit inventory preview and confirmation. Time checks are defense-in-depth; the host must bind the source proof to the source user's existing provider association and consume it once.

Transfers MUST preserve billing entitlements and tenant/child/admin permissions according to the host app's domain rules. In the same transaction, `commitAndQueueSessionRevocation` must fence source authentication, persist committed state, and queue durable session revocation. The fence must deny both existing source sessions (including cached/bearer sessions) and new source sign-ins until the host's retirement policy is resolved. An outbox alone does not close the interval before its worker runs. Account deletion and external side effects remain host responsibilities.

`npm test` runs unit checks plus a disposable SQLite host adapter with real transactions and constrained writes. The tests inject failure after domain transfer, provider reassociation, intent commit, source fencing, outbox enqueue, and immediately before transaction commit. Each failure leaves the original state intact after reopening the database, and a retry produces one outbox task. Further tests cover source ownership changes, tenant exclusions, serialized repeated confirmation, preserved billing ownership, and durable revocation retry after a simulated worker failure before acknowledgement.

The fixture's source-authentication fence demonstrates the required contract; it does not integrate that fence with Better Auth, a host session cache, or a real identity provider. Revocation is simulated with fixture session rows. The two competing confirmations use a single-process transaction queue, not a test of PostgreSQL/MySQL row locks or multi-process isolation. Failure injection and database reopening do not substitute for process-kill or host-infrastructure tests.

Release gates remain: host transaction/locking implementation, provider-proof ownership and one-use consumption, actual session/cache fencing and revocation, domain-policy review, production-dialect concurrency, worker crash recovery, and UI/security sign-off. No real users or production data are merged by this suite.
